## Как попросить точечное изменение

Можно назвать нужный блок: «верни только подвал», «оставь цвета, но верни первый экран» или «поменяй размер золотой эмблемы». Карта выше показывает компонент, стили и коммит. Фотография первого экрана меняется через `lib/home-presentation.ts`; цвета — через токены в `app/globals.css`.

Например, чтобы вернуть прежнее оформление подвала, на актуальной чистой `main`:

```bash
git revert 15868fa94a85f60d56c7ca0ac9f4aa09f5907f11
npm run build
node node_modules/typescript/bin/tsc --noEmit
```

Так появляется новый коммит отмены. Затем нужно проверить подвал на телефоне и компьютере, отправить новый коммит в `main` и публиковать именно его полный SHA. Остальные блоки и текущая общая палитра сохраняются.

Общая дизайн-система — основание для всех обновлённых блоков. Её не отменяют отдельно, пока эти блоки используются. Если нужен другой цвет или шрифт, изменяют соответствующие токены; если нужен полный возврат, отменяют все визуальные коммиты в обратном порядке.

## Полный возврат к состоянию перед редизайном

На актуальной чистой `main`, после проверки последующих изменений:

```bash
git revert --no-commit a48383c87c5b36d54f592037f0f83082b430ef7b cd42f884058f3e41537c323b8ae4a3b5d444fafd a31975018774f3879ddfd80f2e72c86254ef92ae dc36c53cc853bbb070820124a0ba1594632afa58 15868fa94a85f60d56c7ca0ac9f4aa09f5907f11 359ad490793efce7ab1c76dc0b9c062bd2331cc9 47a453921a275dc38a6180d6fde97f021af8153c
git commit -m "Restore Valore appearance before the graphite redesign"
npm run build
node node_modules/typescript/bin/tsc --noEmit
```

Это отменяет семь визуальных коммитов — от раздела бренда до общей основы. Техническая правка прав чтения SVG и документация остаются. В текущей истории проверена трёхсторонняя модель Git: точечная отмена каждого из шести блоков проходит без конфликтов, а полная отмена возвращает все визуальные исходники к `a9a5843`. Рабочие файлы, `main` и production при этой проверке не откатывались. Будущие изменения могут потребовать разрешения конфликтов и новых проверок.

После проверки восстановленный коммит отправляют в `main`. В GitHub Actions запускают **Production website → Run workflow**:

- `mode`: `deploy`;
- `commit`: полный SHA нового коммита восстановления.

Workflow разрешает только продвижение вперёд от текущего серверного HEAD. Поэтому отправлять в него прежний `a9a5843` после обновления нельзя: такой запуск будет отклонён. Используем новый коммит восстановления, сохраняя историю GitHub.

## Что делает деплой

Существующий workflow собирает выбранный полный SHA в отдельной временной папке, затем переключает только frontend `landing`. PM2 работает через пользователя `deploy`. API `landing-api`, база, загруженные товарные фотографии и текущая главная фотография не изменяются. Изменения в `server/` и `deploy/` отсутствуют.

Отдельная техническая правка задаёт права чтения только каталогу `public/brand` и двум официальным SVG, затем проверяет их чтение от `deploy`. Причина — ограничительный `umask` у SSH-процесса `root`; без этой правки новые публичные файлы могли бы быть недоступны приложению.

Во время переключения workflow сохраняет старые `.next` и `node_modules` и пытается вернуть их при ошибке. После успешного завершения временные старые сборки удаляются. Долговременное восстановление обеспечивается сохранённым кодом и новой сборкой коммита возврата; это не постоянный архив бинарных сборок.
