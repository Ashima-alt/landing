## Проверки

Подготовленная сборка и отдельная проверка TypeScript прошли. В Chromium проверены ширины 320, 375, 390, 430, 768, 1024 и 1440 px: нет горизонтального переполнения, текст и кнопка находятся внутри рекламной области, изображение загружается. Скриншоты и измерения локальной сборки сохранены в `/workspace/scratch/valore-lifestyle-hero-preview/`. YAML и Bash workflow прошли синтаксическую проверку.

Workflow собирает новую версию до переключения сайта, управляет только frontend `landing` через PM2 пользователя `deploy` и проверяет чтение/HTTP-доступ к новому WebP. При ошибке переключения предусмотрен возврат предыдущей сборки. API, база, каталог и загруженные фотографии не обновляются.

## Возврат и точечные изменения

Для полного возврата только этого визуального обновления на актуальной чистой `main`:

```bash
git revert 472fe1f712a2fabb5405ebc51613405d45ad3b26
npm run build
node node_modules/typescript/bin/tsc --noEmit --incremental false
```

После проверки публикуют новый коммит восстановления через существующий workflow. Старый SHA не подают как цель деплоя: workflow требует продвижение вперёд. Техническая проверка доступности картинки безопасно пропускается, когда файл отсутствует, поэтому её не нужно отменять при возврате визуального коммита.

Для возврата одного блока сравнивают его файлы из таблицы с тегом `before-hero-2026-10-12`, сохраняют изменение новым коммитом, проверяют зависимые разделы и только затем публикуют. Это позволяет независимо менять фон и blur, шапку либо эмблему, сохраняя мобильную сетку товаров.
