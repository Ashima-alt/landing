# Valore Milano: предварительный план SEO, производительности и развития

Дата проверки: 9 октября 2026 года, 15:29 МСК. Аудит относится к исходному состоянию сайта перед текущим визуальным редизайном, коммит `a9a5843896881844c8892af5f29097047015093c`.

Это рекомендации для отдельного этапа. Метаданные, robots, sitemap, сервер, товары, интеграции и настройки поисковых систем в рамках аудита не изменялись. В production выполнялись только публичные GET-запросы; заявки, заказы и записи в базе не создавались.

## Что удалось установить

| --- | --- | --- |
| Главная, каталог, действующая карточка товара | HTTPS, HTTP 200 | Сайт и публичный каталог доступны. Это не подтверждает индексацию в поисковых системах. |

| Содержание description | Утверждения о фарфоре и ручном изготовлении в Италии | Подтверждающих материалов в доступных источниках не обнаружено; такие обещания требуют проверки. Это не следует автоматически переносить в новые тексты. |
| Canonical и структурированные данные | Не обнаружены в проверенном HTML и исходном коде | Не задано явное предпочтение адресов; нет отдельной разметки организации, товара и хлебных крошек. |

| Серверный HTML каталога и товара | Нет названий и ссылок на товары; данные загружаются в браузере через `useEffect` | Поисковый робот должен выполнять JavaScript и дождаться API. | `/cart`, `/checkout`, `/profile` | HTTP 307 → `/catalog`, как и в исходном коде | Действующий публичный сайт сейчас является каталогом. Компоненты корзины, профиля и checkout присутствуют в проекте, но не подключены к этим страницам. |
| Товарные данные | 51 из 53 товаров без описания, у всех пустое поле размера, у всех одно фото; материал заполнен | Для убедительного представления продукции требуется работа с подтверждёнными характеристиками и фотографиями. Данные в ходе аудита не исправлялись. |
| Изображения | `images.unoptimized: true`; три проверенных JPEG товара — около 122–159 КиБ, hero — около 84 КиБ | CSS и `sizes` задают отображение, но при отключённом оптимизаторе Next.js не создаётся набор уменьшенных файлов для разных экранов. Размеры выборки не описывают все 53 изображения. |
| Кэширование проверенных изображений | `Cache-Control: public, max-age=0` | Браузеру приходится перепроверять актуальность файлов при повторных посещениях; это не означает, что он каждый раз скачивает весь файл. |
| Существующая Vercel Analytics | Компонент подключён в layout, `/_vercel/insights/script.js` отвечает 404 | На текущем сервере этот способ загрузки аналитики не работает. Новый сервис не подключался. |

Контакты в подвале остаются согласованными заглушками: `+7 (938) 000‑00‑00`, `info@example.ru`, «Грозный, Россия». Сейчас это принято пользователем; перед привлечением покупателей следует заменить их на действующие данные.

В неиспользуемом `StoreProvider` корзина хранится в состоянии React, без `localStorage`. Неиспользуемый `CheckoutContent` имитирует обработку таймером и не отправляет заказ на сервер. В маршрутах API нет обработчика покупательских заявок или заказов. Поэтому нельзя считать реальную покупку или сохранение корзины между посещениями уже реализованными. Активировать эти заготовки одним изменением оформления нельзя; нужен самостоятельный функциональный этап.

## 1. Критически важно перед активным продвижением

Сложность ниже означает примерный объём разработки, а не срок. Согласование фактов, получение фотографий, документов и доступов может занимать больше времени, чем код.

| Рекомендация | Что требуется | Ожидаемая польза | Сложность |
| --- | --- | --- | --- |
| **Согласовать достоверные сведения о бренде и товарах** | Подтвердить происхождение, год основания и характеристики по фирменным документам. Убрать или скорректировать неподтверждённые `Handcrafted in Italy` и `premium porcelain` в отдельном согласованном SEO-изменении. Новую историческую часть публиковать только после подтверждения владельца. | Посетители и поисковая выдача получают согласованные, достоверные обещания бренда. | Низкая для текста и кода; зависит от материалов владельца. |
| **Подготовить рабочий способ обращения** | Согласовать реальные телефон и email, ответственного за обращения и сценарий: заявка на товар, консультация либо полноценный заказ. Если нужна форма — отдельно реализовать серверное получение, валидацию, уведомление и честный результат отправки. Уточнить необходимость политики обработки персональных данных. | Реклама и поисковый трафик приводят к обращениям, которые действительно доходят до компании. | Низкая для контактов; средняя для формы; высокая для полноценного интернет-магазина. |
| **Дать важным страницам самостоятельные поисковые метаданные** | Русский язык документа; отдельные title/description для главной, каталога и каждого товара; единый `metadataBase`, canonical и корректные Open Graph. Существующие URL товаров сохранить. Не пытаться продвигать все запросы одной главной страницей. | Более понятные сниппеты и превью ссылок, меньше дублей, корректное описание содержания страницы. | Средняя: данные товара сейчас загружаются на клиенте. |
| **Сделать товарные страницы доступными в исходном HTML** | Серверно отдавать первоначальные товарные данные и ссылки, оставляя интерактивные фильтры и галерею существующими клиентскими компонентами. Проверять реальное отсутствие товара на сервере и возвращать 404; ошибку API отличать от отсутствующего товара. | Роботы и посетители раньше получают содержание; уменьшается зависимость поиска от выполнения JavaScript. | Средняя; требуется аккуратная работа с границей server/client без переписывания проекта. |
| **Настроить базовую структуру индексации** | Выбрать основной HTTPS-хост, настроить постоянный redirect альтернативного хоста и проверить HTTP → HTTPS. Создать sitemap с действующими публичными товарами и robots; не включать API, админку и служебные страницы. Закрытие админки в robots не заменяет авторизацию. | Поисковым системам проще находить нужные страницы и выбирать единые адреса. Sitemap не гарантирует индексацию. | Средняя: кроме Next.js потребуется отдельное согласование серверной конфигурации. |
| **Проверить состояние Яндекса и Google через аккаунты владельца** | После согласования подключить Яндекс Вебмастер и Google Search Console, подтвердить домен и отправить sitemap. Проверить статус главной, каталога и нескольких товаров, исключения, выбранные canonical и доступность для роботов. | Фактическая диагностика индексации и ошибок вместо предположений по внешнему виду сайта. | Низкая–средняя; нужны аккаунты и доступ к подтверждению домена. Сейчас они не подключались. |

## 2. Желательно улучшить после базовой подготовки

| Рекомендация | Что требуется | Ожидаемая польза | Сложность |
| --- | --- | --- | --- |
| **Заполнить карточки полезными данными** | Короткое уникальное описание назначения, подтверждённые материал, размер, комплектность и правила ухода. Добавить оригинальные фотографии деталей и масштаба предмета. По возможности заменить временную фотографию первого экрана на Valore. Не придумывать свойства вместо производителя. | Посетитель лучше понимает товар и может осознанно отправить заявку; у страницы появляется самостоятельное поисковое содержание. | Средняя; основная работа — контент и съёмка. |
| **Собрать семантику по фактическому ассортименту** | Начать с брендовых запросов «Valore Milano», «посуда Valore», «кухонные принадлежности Valore», а затем подтвердить спрос на группы вроде шумовок, половников, венчиков и силиконовых лопаток. Уточнять материал и сценарий использования только по реальным характеристикам. Для сильных категорий подготовить полезные посадочные страницы; не создавать страницы под каждую комбинацию фильтров. | Привлечение посетителей с интересом к конкретным товарам, понятная структура каталога. | Средняя; частотность и конкуренция пока не проверялись, список — отправная точка. |
| **Привести структуру категорий к единому виду** | Согласовать названия и язык категорий: API содержит русские категории и `Piatti`, `Tazze`, `Posate`, `Set`, а также очевидные опечатки. Проверить наличие товаров в категориях. Определить правила canonical для фильтров; категории с собственным контентом отделить от временных фильтров. Изменение существующих URL — только с продуманными redirect. | Посетители легче ориентируются; поисковая структура меньше дублируется. | Средняя; потребуется согласование изменений данных. |
| **Оптимизировать доставку изображений** | Проверить все оригиналы и реально загружаемые размеры на телефоне; выбрать генерацию производных WebP/AVIF или штатную оптимизацию Next.js. Сохранить исходники, пропорции и читаемость деталей. Для файлов с уникальными именами настроить разумное долговременное кэширование после проверки процесса замены файлов. | Меньше трафика и ожидания на мобильных сетях, быстрее повторные посещения. | Средняя; изменение пути доставки `/uploads` следует согласовать отдельно. |
| **Измерить производительность и исправлять по данным** | Проверить главную, каталог и товар на мобильном профиле Lighthouse/PageSpeed, отдельно оценить LCP, INP и CLS. Затем посмотреть полевые данные, если трафика достаточно. Проверить цепочку JavaScript → API → фото, появление товаров после загрузки, плавность фильтров и меню, загрузку двух гарнитур. | Можно выбрать действительно полезные оптимизации и проверить их эффект. | Низкая для первых замеров; средняя для найденных улучшений. |
| **Привести аналитику к реальному окружению** | Отдельно согласовать, нужна ли текущая Vercel Analytics на собственном сервере и чем измерять обращения. Устранить её существующий 404 при выбранном решении; не устанавливать сразу несколько счётчиков. Определить события просмотра товара и успешного обращения с учётом приватности. | Понимание источников посетителей и реальной отдачи продвижения, меньше бессмысленных сетевых запросов. | Низкая–средняя; подключение сервиса требует согласования. |

Что уже полезно для производительности: шрифты используются через `next/font` и `display: swap`; фото первого экрана помечено `priority`; квадратные области фотографий резервируют место. Список зависимостей сам по себе не доказывает, что весь код этих библиотек отправляется посетителю: сокращать его стоит после анализа фактических JS-файлов.

Core Web Vitals в этом аудите **не измерялись**. Нельзя объявить их хорошими или плохими по одной проверке размера JPEG. Целевые ориентиры Google — LCP ≤ 2,5 с, INP ≤ 200 мс, CLS ≤ 0,1 на 75-м перцентиле реальных посещений; лабораторная оценка и полевые данные не равнозначны.

## Предлагаемая последовательность отдельного этапа

1. Согласовать факты о бренде, действующие контакты и цель сайта: каталог с заявками или интернет-магазин.
2. Подготовить серверное содержание, метаданные, адреса и карту сайта; проверить выдачу корректных HTTP-статусов.
3. С разрешения владельца подтвердить сайт в поисковых кабинетах и проверить реальную индексацию.
4. Дополнить данные товаров, измерить скорость и выбрать обоснованные оптимизации.
5. Согласовать аналитику и тестовое продвижение, оценивать реальные обращения.

## Источники и ограничения

Исходный код: `app/layout.tsx`, `app/catalog/page.tsx`, `app/product/[id]/page.tsx`, перенаправления `app/cart`, `app/checkout`, `app/profile`, `components/home/featured-products.tsx`, `components/catalog/catalog-content.tsx`, `components/checkout/checkout-content.tsx`, `components/product/product-gallery.tsx`, `lib/store-context.tsx`, `lib/api.ts`, `lib/types.ts`, `next.config.mjs`, `server/src/index.ts` и маршруты сервера, `deploy/nginx/amir-landing.conf`, существующий workflow production deploy. Дополнительно проверены публичные HTTP-ответы, перечисленные выше.

Публичные ответы показывают текущее поведение production, а файл Nginx в репозитории — шаблон конфигурации; он не доказывает точное состояние конфигурации работающего сервера. В поисковые кабинеты доступа нет. Google и Яндекс могут выполнять JavaScript, но фактические позиции, число проиндексированных страниц, трафик и полевые показатели скорости без соответствующих данных неизвестны. При подготовке будущей публикации эти результаты следует перепроверить.
